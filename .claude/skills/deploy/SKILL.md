# Deploy

Этот Skill используется для деплоя портфолио на production-сервер SWEB.

## Environment

Server:
`sweb`

Remote path:
`/home/l/linebaru/dopler/public_html`

Production URL:
`https://dopler.lineband.ru/`

Deployment tool:
`rsync`

## Verification

- Verify only the configured Production URL.
- Do not guess or search for alternative domains.
- Do not check unrelated domains.

## Deployment rules

* Работай из корневой папки проекта.
* Перед любым реальным деплоем обязательно выполняй `rsync` в режиме dry-run (`-n`).
* Перед реальным деплоем покажи пользователю, какие файлы будут отправлены.
* Не используй `--delete` без явного подтверждения пользователя.
* Не удаляй файлы на сервере без явного подтверждения пользователя.
* Деплой только production-файлов.
* После загрузки обязательно проверь наличие и корректность `index.html`.
* Если обнаружена ошибка, останови деплой и сообщи о ней пользователю.

## Files excluded from deployment

Всегда исключай:

* `CLAUDE.md`
* `.claude/`
* `tmp/`
* `.DS_Store`

## Deployment procedure

### 1. Check project

Перед деплоем:

* убедись, что работаешь из корня проекта;
* проверь структуру проекта;
* определи production-файлы;
* убедись, что исключённые файлы не попадут в деплой.

### 2. Run dry-run

Сначала выполни `rsync` с `-n`.

Используй:

`-rvz`

Не используй `-a` или `--delete-excluded`.

### 3. Show deployment plan

После dry-run сообщи пользователю:

* какие файлы будут загружены;
* какие файлы исключены;
* есть ли потенциально опасные изменения;
* используется ли удаление файлов на сервере.

Не выполняй реальный деплой до подтверждения пользователя.

### 4. Deploy

После подтверждения выполни реальный `rsync`.

Не удаляй файлы на сервере, если пользователь явно не разрешил это.

### 5. Verify deployment

После загрузки:

* проверь наличие `index.html` на сервере;
* проверь, что файл доступен;
* если возможно, проверь production-сайт;
* сообщи пользователю результат проверки.

## macOS / rsync compatibility

На macOS `openrsync` может конфликтовать с `-a` / `--delete-excluded` при работе с rsync 3.1.2.

Поэтому для этого проекта используй:

`-rvz`

и не используй:

`-a`

`--delete-excluded`

без отдельного подтверждения и необходимости.

## Failure handling

Если любой этап завершается ошибкой:

1. останови дальнейшие действия;
2. сообщи, на каком этапе произошла ошибка;
3. покажи текст ошибки;
4. не выполняй следующие destructive actions автоматически.

Никогда не скрывай ошибку и не сообщай об успешном деплое, если проверка не пройдена.
